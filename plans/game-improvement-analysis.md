# Анализ возможностей улучшения Last Hearth

Детальный технический аудит кодовой базы (июль 2026). Сгруппировано по
областям с указанием файлов, строк и конкретных правок.

---

## 1. Архитектура фронтенда (критично)

**Проблема:** `public/game.js` содержит ~7795 строк и совмещает утилиты,
API-слой, состояние игры, шаблоны и менеджеры. При этом `README.md` обещает
модульное разбиение (`game-core.js`, `game-systems.js`, `game-ui.js`,
`game-api.js`), которого фактически нет. Функции `showScreen`, `useItem`,
`attackBoss` вызываются из `Templates` (строки 853, 875), но НЕ определены в
этом файле — значит либо они в другом (неподключённом) файле, либо UI
сломан. `index.html` подключает только `game.js`.

**Улучшения:**
- Разбить `game.js` на ES-модули: `state.js`, `api.js`, `ui.js`, `systems.js`,
  `core.js` с явным `import/export`.
- Убедиться, что `showScreen`, `useItem`, `attackBoss` реально существуют и
  подключены (иначе весь клиент не работает).
- В `index.html` добавить `<script type="module" src="core.js">`.

## 2. Баланс опыта и прогрессии (P0)

**Файл:** `utils/gameConstants.js` строки 14-18, `routes/game/world.js` 361-366.

`getExpForLevel(level) = level * 500` — линейная. На 50 уровне нужно 25 000 XP.
Поиск даёт 6-15 XP (×множитель риска макс 1.7 ≈ 25 XP). PvP — 50 XP.
Гринд становится невозможным после ~20 уровня.

**Улучшения:**
- Изменить кривую на мягкую экспоненту: `base * level^1.3` или
  `500 * level * (1 + level/20)`.
- Привязать XP к уровню локации (локации 5-7 должны давать ощутимо больше).
- Увеличить базовый XP за поиск или дать "combo" за серию поисков.

## 3. PvP: формулы боя (P1)

**Файл:** `routes/game/pvp.js` строки 425-464.

- Урон `strength*2 + agility*0.5` — сила доминирует, ловкость почти не влияет.
- Защита `min(75%, endurance*0.5)` — при `endurance >= 150` всегда 75% редукции.
  Танк неуязвим.
- Уклонение `min(25%, agility*0.5)` — при `agility >= 50` всегда 25%.

**Улучшения:**
- Ограничить эффективность статов: `reduction = endurance/(endurance+K)*maxCap`
  (насыщение, а не жёсткий caps).
- Добавить влияние уровня/экипировки на урон.
- Снизить caps до 50%/15% или сделать их soft.

## 4. PvP: незащищённый фарм и телепорт (P1)

**Файл:** `routes/game/pvp.js` строки 502-591.

- Победитель крадёт 10% монет (max 10000), проигравший телепортируется в
  безопасную зону. Нет кулдауна на повторную атаку ОДНОГО и того же игрока
  (можно фармить богатого игрока раз за разом, пока он не уйдёт в safe).
- Кулдаун `pvp_battle` проверяется, но не устанавливается после боя! В
  `attack-hit` при завершении нет записи в `pvp_cooldowns`.

**Улучшения:**
- В `attack-hit` при `battleEnded` вставить
  `INSERT INTO pvp_cooldowns (player_id, cooldown_type, expires_at) VALUES ($1,'pvp_battle', NOW()+interval '5 min')` для победителя и проигравшего.
- Добавить защиту от повторной атаки одной цели (отдельный короткий кулдаун
  на пару attacker-target).
- Ограничить кражу монет процентом от минимума(атакующий, защитник).

## 5. Энергия: сброс таймера регена (P0 — баг)

**Файл:** `routes/game/world.js` строки 386-389, `routes/game/pvp.js` 414-421.

При трате энергии ставится `last_energy_update = NOW()`. Реген считается от
этого поля (`ENERGY_REGEN_INTERVAL_MS` в game-helpers). Итог: каждое действие
сбрасывает накопленный реген. Игрок, потративший энергию сразу после входа,
ждёт полную минуту вместо дробного восстановления.

**Улучшения:**
- Не трогать `last_energy_update` при трате; реген должен идти от реального
  прошедшего времени независимо от трат.
- Вынести пересчёт энергии в единый хелпер `recalcEnergy(player)` и вызывать
  перед любой проверкой.

## 6. Радиация/инфекции: рассинхрон констант (P1)

**Файл:** `utils/gameConstants.js` 233 vs `routes/game/world.js` 379.

`DEBUFF_CONFIG.radiation.damagePerLevel = 1`, но в world.js при уровне >=5
урон берётся как `DEBUFF_CONFIG.radiation.damagePerLevel || 2` — то есть всегда
2, константа игнорируется.

**Улучшения:**
- Использовать `damagePerLevel` напрямую (убрать `|| 2`).
- В `world.js` расчёт `radiationGain` дублирует логику
  `calculateLocationRiskProfile` (defense уже посчитан). Стоит брать
  `riskProfile.radiationPressure` вместо повторного `baseRadiation - defense`.

## 7. Отсутствие проверки здоровья (P1)

**Файл:** `routes/game/world.js` 175-213.

Поиск лута разрешён при `health = 0` (игрок "мёртв"). Только энергия проверяется.
Можно бесконечно искать будучи мертвым.

**Улучшение:** добавить `if (health <= 0) return { error: 'Сначала вылечись' }`.

---

## 8. Производительность лута (P2)

**Файл:** `routes/game/world.js` 46-87 `getRandomLootItem`.

`ORDER BY random()` на таблице `items` (растущей) — полное сканирование +
сортировка каждый поиск.

**Улучшения:**
- Предподсчитать пул ID по rarity+type в памяти (кэш при старте).
- Выбирать случайный ID из кэша и делать `WHERE id = $1`.
- Или `TABLESAMPLE` / оконные функции.

---

## 9. Хрупкая привязка ключей боссов (P1)

**Файл:** `routes/game/world.js` 326-339.

Поиск ключа через `name LIKE '%' || $1 || '%'` по русскому имени босса —
ломается при переименовании/опечатке.

**Улучшение:** хранить `boss_id` в `keyChances` и джойнить
`boss_keys`/`items` по `required_key_id`, а не по строковому совпадению.

---

## 10. Нет лимита инвентаря (P2)

**Файл:** `routes/game/world.js` 346-359.

Инвентарь — массив JSONB без ограничения слотов. Может раздуться до мегабайт,
тормозя каждый `SELECT *`.

**Улучшение:** `MAX_INVENTORY_SLOTS = 100`, при переполнении — авто-продажа
или отказ.

---

## 11. Дублирование систем ачивок (P2)

**Файл:** `utils/game-helpers.js` 522-562 `initAchievementsTable` vs
`db/schema.js` 360-412.

В схеме вшиты 4 ачивки ("Первое убийство" и т.д.), в `initAchievementsTable` —
ещё 19 старых. Обе пишут в одну таблицу. Возможен дубляж/путаница в UI.

**Улучшение:** оставить единый источник (схема), удалить старый набор или
пометить `deprecated`.

---

## 12. Кэширование рендера (P2)

**Файл:** `public/game.js` 751-779 `RenderCache`.

Кэш только для inventory/market/bosses, без инвалидации при действиях. После
использования предмета UI может показать старое.

**Улучшение:** вызывать `RenderCache.clear(section)` в колбэках
`useItem`, `attackBoss`, `purchase` и т.д.

---

## 13. Безопасность/валидация входа (P2)

**Файл:** `routes/game/world.js` `search`.
- `luck` берётся из БД напрямую — ок.
- Но `equipment` парсится через `safeJsonParse` без проверки структуры —
  невалидная экипировка может уронить расчёт защиты.

**Улучшение:** валидировать `equipment` через `normalizeEquipment()`.

---

## 14. Realtime/PvP синхронизация (P2)

**Файл:** `utils/realtime.js` (не читал детально), `routes/game/pvp.js`.

В `attack-hit` нет таймаута хода и нет push-уведомления противнику. Бой
зависит от polling клиента.

**Улучшение:** через `ws` слать событие противнику при ударе/завершении,
добавить `turn_timeout` (например, 30 c) с авто-завершением.
